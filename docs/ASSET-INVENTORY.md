# STARBOX COFFEE graphics inventory

Release 2.4.1 keeps the current course, switchbacks, collisions, recipes and
physics intact. The experience combines procedural Three.js geometry and
materials with a few authored image assets. Its current visual direction is a
compact stylized café with crisp pixel characters over softly graded 3D.

## What draws the game

- **Procedural 3D geometry:** `experience/environment.js` builds the mug,
  glass handle and rim, café room, counter, windows, pendant lights, ledges,
  biscuits, coffee surface, steam, bubbles and condensation from Three.js
  primitives and custom buffer geometry. `experience/collectibles.js` builds
  beans, milk drops and stars as shaded meshes. `experience/main.js` places
  this scene; course layout and collision rules live separately in
  `experience/rules.js`.
- **Materials and shaders:** `experience/cafe-materials.js` extends Three.js
  materials with shared window and lantern lighting, surface detail and glaze
  highlights. `experience/barista.js` uses a small custom sprite shader for
  scene-depth occlusion and warm edge/bounce light. `experience/diorama.js`
  adds a restrained depth-aware softness and highlight glow to the distant
  scene. Coffee uses a procedural brown/crema shader. Shadows, glows and the
  café sign use generated canvas textures, rather than imported image files.
- **UI:** `experience/ui.js` draws the cover, selection screens, compact HUD,
  menus and results into an `OffscreenCanvas` resized to the native viewport,
  then displays it as a WebGL texture. Buttons and responsive layout are game code. There is no
  HTML/CSS interface in the experience.

## Existing sprites and files outside the active art path

The current game has two selectable baristas: active Milo uses the 2.4.1
registered atlas in gameplay and selection, while Mira uses her original V2 atlas. The earlier Milo
atlas is recoverable from the 2.4 Git checkpoint; its original source remains in `tools/art-source/milo-polish-original.png`. The
older `experience/assets/barista.png` and `sprites.json` describe a 32×40,
10-frame prototype sprite; `barista-preview.png`, `cover.png`,
`card-espresso.png` and `card-latte.png` are legacy assets and are not loaded by
the current experience. The `build/` GLBs, shaders and Blender source belong to
the original lot attraction; the current playable experience builds its café
in code rather than loading those models. These files should not be mistaken
for assets in the active rendering path.

## Focused art direction

For future polish, keep the tested course and physics fixed and refine the
existing asset families one at a time. Work from an agreed palette, material
and pixel-scale guide; author pixel sprites on a deliberate native grid with
consistent silhouettes, palette ramps and foot registration; and create
coherent, tileable material textures that match the geometry's texel scale.
Use reference-led original art, preserve source and prompt/provenance, and
keep import steps deterministic. Review each change in the official DevKit at
native gameplay size and across desktop and phone framing, checking sprite
crispness, atlas edges, readability and lighting against the existing café.
This supports a more professional pixel-art/HD-2.5D finish while retaining the
current composition, course, switchbacks and physics.
